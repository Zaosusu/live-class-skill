# 收音原理与「屏幕录制」权限授权（零安装方案）

本技能**不安装任何软件**：系统声音直接用 macOS 自带的 **ScreenCaptureKit** 捕获
（macOS 14+；Apple 给 OBS、各类会议转录软件用的官方接口）。
不需要虚拟声卡（BlackHole/Soundflower）、不需要 ffmpeg、不需要切换系统输出设备，
用户可以照常戴耳机/外放听课，声音在系统混音处被"旁路"采样，互不干扰。

## 为什么 macOS 需要一次性授权

Windows 有 WASAPI 回环接口，任何程序可自录系统声；macOS 出于隐私设计没有这条路，
唯一官方途径是 ScreenCaptureKit——它把「屏幕 + 系统声音」捕获统一收在
**「屏幕录制」隐私权限**下。所以即便只取声音，也要授权一次屏幕录制。

这属于**系统隐私授权（可随时在设置里关闭）**，不是安装软件。

## 一次性授权步骤

1. 打开 **系统设置 → 隐私与安全性 → 屏幕录制**；
2. 勾选运行本工具的 App：
   - 从终端（Terminal / iTerm）或 IDE 跑的 → 勾**对应的终端 / IDE**；
   - 若列表里没有，点列表下方 **＋** 手动从「应用程序」里添加；
3. **完全退出并重启该 App**（权限变更必须重启才生效，重要！）；
4. 重跑 `bash <技能目录>/scripts/setup.sh`，看到
   `[OK] 「屏幕录制」权限已授予` 即完成。

命令行快速探测（每次都能用）：
```bash
python3 <技能目录>/scripts/record.py check
```

## 授权后仍录不到声音的排查

| 现象 | 处理 |
|---|---|
| 重启后 `check` 仍报未授权 | 确认勾的是**实际承载本工具**的 App；必要时 `＋` 手动添加再重启 |
| 有权限但没分块产生 | 系统音量是否为 0 / 静音键按下；直播页是否真的在播（打开页面听一下） |
| 有分块但转写为空 | 说话内容少/间隔长属正常；确认页面在放人声（音乐/白噪音会识别为空） |
| 个别视频无声音 | 可能受 DRM 保护（版权流），ScreenCaptureKit 会被系统静音，属平台限制，换浏览器无解 |

## 权限撤销/重置（如需重来）

```bash
tccutil reset ScreenCapture  # 重置所有 App 的屏幕录制授权，然后重新按上文授权
```

## 测试建议（无需真直播）

用任意能出声的网页（B站视频/音乐站）播一段，跑 25 秒左右后看
`<session>/transcripts/segments.jsonl` 是否有文字，即可验证全链路。
