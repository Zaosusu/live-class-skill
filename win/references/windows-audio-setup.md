# Windows 版内录原理与零第三方说明

## 一句话

Windows 版用**系统自带**的 **WASAPI loopback（回环采集）** 录制"系统正在播放的声音"，
不装虚拟声卡、不用 ffmpeg、不装任何第三方录音软件、不切换输出设备，也不驱动浏览器。

## 原理回顾

- 系统所有 App（浏览器直播、腾讯会议、播放器等）播放的声音，会先进入 Windows 的
  **音频引擎（Audio Engine）**，再混音送到"默认输出设备"（扬声器/耳机）。
- **WASAPI loopback** 让一个程序以"只读"方式旁听这个混音流——即拿到"系统正在播放的一切声音"。
  OBS Studio、各类"录制扬声器(输出)"的会议转录软件在 Windows 上用的正是这个接口。
- 本项目用 Python 标准库 `ctypes` 直接调用系统 Core Audio COM 接口
  （`IMMDeviceEnumerator` / `IMMDevice` / `IAudioClient` / `IAudioCaptureClient`），
  **不引入任何第三方 Python 包**做录音。产出与 mac 版完全一致：16kHz / 单声道 / 16bit 的 wav 分块。

## 为什么零第三方也能录

| 需求 | mac 版对应 | Windows 版对应 |
|---|---|---|
| 抓"正在播放的声音" | ScreenCaptureKit（苹果系统自带） | WASAPI loopback（微软系统自带 Core Audio） |
| 需要的权限/前置 | 一次性"屏幕录制"授权 | 无需授权；需有"启用的默认输出设备" |
| 需要装的东西 | 无 | 无（录音本身不需要装任何东西） |

> 转写用的 sherpa-onnx（本地离线 ASR）与 mac 版共用，属"转写引擎"而非"内录工具"；
> 它只在你需要"把声音转成文字"时才需要，且是本地离线、不上传。

## 为什么绝不用浏览器自动化（防封号）

很多"自动听课"脚本会去驱动浏览器（selenium/playwright/CDP）自动打开直播间、抓流、点按钮，
这在直播平台眼里等于"机器人代看/录屏工具"，极易触发风控封号。
本方案刻意避开：
- **不做任何浏览器自动化**：不打开、不注入、不点击、不读页面、不抓直播流地址。
- 打开直播网页由**用户自己在浏览器里完成**，本技能只"旁听系统声音"，对平台零指纹、零介入，
  与"你自己开着直播外放、旁边放个录音笔"完全等同，最安全。
- 详见仓库根 `AGENTS.md` 的铁律——这条约束会随仓库一起约束所有 AI agent。

## 常见问题

### setup 检查第一段报"[缺失] 内录不可用"
本机当前没有"已启用的默认音频输出设备"。处理：
1. 插好/启用一个输出设备（扬声器、耳机、USB 声卡、蓝牙耳机）；
2. 在 `设置 → 系统 → 声音 → 输出` 里确保有一个设备且非"已禁用"；
3. 重跑 `python win\scripts\setup.py`。

### record start 报 "初始化失败 HRESULT=0x88890008"
`AUDCLNT_E_DEVICE_INVALIDATED`：默认输出设备被禁用/拔出/驱动重置。
启用默认输出设备或插好耳机后重试即可。

### 明明在播放，为什么没转出文字
先确认三点：
1. 系统音量与页面音量非 0；
2. 播放的不是"受 DRM 保护"内容（个别平台会静音 loopback）；
3. 是否正在播放（而不是暂停/黑屏）。
多数情况是"没在出声"，按 skill 第 6 步排查即可。

### 会不会录到我的麦克风 / 影响我用麦克风
不会。loopback 只读"输出(播放)"混音，**不碰麦克风**，不影响你在腾讯会议/直播里连麦说话。

### 录音会影响正常外放吗
不影响。loopback 是"旁听"，不改动系统输出，你照常能听到声音。

### 需要一直保持浏览器在前台吗
不需要。只要页面在出声（可在后台播放），系统混音里就有它。你甚至可以最小化浏览器去干别的。
