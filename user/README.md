# user/ —— 本技能用户的听课产出（本地产出，不入版本库）

每场「持续听课」的完整产出自动落盘到本目录，一场一个目录，主播账号+主题+时间全拼在目录名里：

```
user/session/<主播账号>_<直播主题>_<开始时间>/
    ├── meta.json            # 场次元信息（直播间/标题/主播uid与名/听课人/开始时间/段长）
    ├── chunks/seg_*.wav     # 音频分块（近流式默认 5s 一段）
    ├── transcripts/
    │   ├── segments.jsonl  # 逐段结构化转写（实时追加）
    │   └── transcript.txt  # 纯文字稿（实时追加，最终交付物）
    ├── record.log / transcribe.log / listen.log
```

- 目录名 = **自动抓取的主播账号 + 自动抓取的直播主题 + 开始时间**，如 `天津极品相声帮_华为MateXT2发布会_20260907-1738`。
  主播名取不到时自动降级为 `room<直播间号>`。
- `--user <听课人标识>` **只记入 `meta.json`**，不参与目录名。
- `transcript.txt` 是**边听边流式追加**的最终文字稿，可直接打开阅读。
- 本目录内容是**本机/本使用者的听课记录**，体积可能很大（音频+持续增长的稿子），
  因此在 `.gitignore` 中排除、**不进入 git**；它只是仓库工作树里的本地落盘位置。

## 由谁生成

推荐用统一编排命令（一条命令自动听完一整场并实时出字）：

```bash
# 监听 B站直播间，边听边把文字流式追加进 user/session/<主播>_<主题>_<时间>/
python scripts/listen.py --room <B站直播间号> --user <你的标识>

# 没人值守跑一整场（未开播会等、结束自动收尾），放后台：
nohup python scripts/listen.py --room 1816490612 --user me --wait-start \
      > user/listen_me.log 2>&1 &
```

`listen.py` 会自动：抓直播主题建目录 → 内录(5s 近流式小分块) → 秒级增量转写出字 →
检测到下播自动停录收尾 → 产出最终 `transcript.txt`。
转写默认 **GPU 优先、无 GPU 自动降 CPU**，单块失败自动跳过，可稳定跑 60 分钟以上。
